# suji-performance

suji-report 데이터를 기반으로 **성과 문서**(AX 사례, 성장 피드백, 분기 성과 보고)를 작성한다.

**scope: work only**

## 파이프라인 위치

```
/suji-report (집계·정리)
    ↓
/suji-performance (성과 문서 작성) ← 가이드라인 내장
    ↓
ERP 입력 / AX 사례 / CEO 보고 / Confluence
```

## 트리거

- "OKR 써야 해", "성과 피드백 써야 해", "ERP 성과 작성"
- "AX 사례 정리해야 해", "AX 테이블 업데이트"
- "성장 피드백 작성", "분기 성과 정리"

## 커맨드

```
/suji-performance                    → 대화형: 어떤 문서를 쓸지 물어봄
/suji-performance ax [2026-Q1]       → AX 사례 작성/고도화
/suji-performance growth [2026-Q1]   → ERP 성장 피드백 작성
```

## 설정

```
REPORT_PATH=~/Workspace/work/drafts
MEMORY_PATH=~/.claude/projects/-Users-sujicho-Workspace/memory
AX_GUIDELINES=$MEMORY_PATH/feedback_ax_performance_writing.md
```

1. `/suji-report` 분기 리포트 (`~/Workspace/work/outputs/drafts/*_업무성과리포트_*분기.md`)

7. Memory: 프로젝트 맥락, 진행 중 이슈

## 작성 가이드라인 (전 문서 유형 공통)

### 톤·표현
- 비용(만원) 수치 제외 — 시간(시간)·배수(%)로만 표현
- "완전 제거" 같은 과장 금지 → "대폭 절감", "최소화"
- AI가 전부 한 게 아님 → "AI 지원으로", "AI 초안 지원으로"
- 없는 사실 지어내지 않기, 있는 내용 안에서 포장
- **조직 내 참고 자료 수준으로** — 다른 팀원이 봤을 때 불편하지 않게, 비교 표현 금지. 조직 내 참고할 만한 사례로 자연스럽게 포지셔닝

### 프레이밍
- 기획/전략이 핵심 + 직접 구축까지 했다는 점 동시 어필
- **개발본부 PM 관점:** 개발자 리소스 요청 없이 PM이 직접 구축 → 개발팀은 제품 개발에 집중
- **경영진 의사결정 지원:** 확보 시간 → 전략 고도화, BM 대응, 커뮤니케이션 등에 재투자
- "분석 체계", "관리 체계", "보고 체계", "인텔리전스 체계" 등 체계 표현 사용
- AX 유형에 "자동화"만 넣으면 까일 수 있음 → 기획/전략 가치는 본문에 녹이기
- **오가닉·스타수 프레이밍:** PR/콘텐츠 성과를 "스타수 N → N 오가닉 성장 (광고비 $0)" 패턴으로 연결. 읽는 사람이 요점을 바로 파악할 수 있도록 수치 명시 필수
- **실무 적용이 핵심:** GEO 같은 전략은 "내가 빌드했다"가 아니라 "실무에서 반복적으로 적용하여 성과를 뒷받침했다"로 프레이밍. Q&A 포맷·UTM 링크 등 구체적 적용 사례 나열
- 같은 성과를 여러 항목에 교차 배치 — 예: Stars 성장이 "AI 활용"과 "출시 성과" 양쪽에 등장
- 사내 발표·가이드 배포 별도 명시 — 지식 공유·리더십 어필
- "광고비 $0" — 비용 없이 달성한 점을 명시적으로 강조
- AI가 자율적으로 동작하는 점 강조 — "AI 큐레이션 봇이 자동 홍보"

### 구조·가독성
- 불렛 포인트 단문 (줄글 금지)
- **요약 줄 없이 바로 불렛 시작** — 항목별 헤더/요약 줄 제외, 첫 불렛부터 성과 내용
- "AI Agent로 ~" 접두어 — 불렛이 AI 활용으로 시작하는 패턴
- 압축 지표 — "2팀 5개월 → 1명 AI 4일" (Before→After 한 줄 압축)
- 대형 숫자 강조 — 20배, 72만회, 80개국 등 임팩트 있는 숫자 전면 배치
- "#1" 반복 — 1위 달성 사실이 있으면 적극 활용
- 건수 명시 — "AI Agent 기반 업무 자동화 28건" 식으로 총량 표현
- **PR 콘텐츠 총합 명시** — 보도자료+라운지+Medium+이미지 등 합산 건수를 항목 첫 줄에
- 효율성 요약: **생산성 N% 달성** 패턴 + 통상 X시간 → AI Y시간, **Z시간 확보**
- 0→1 신규 구축 강조
- 비개발 직군이 AI로 개발까지 수행한 점 강조
- Slack 알림 연동 → 누락 방지 강조
- **프로젝트명은 구체적으로** — "PR 패키지" 같은 약칭 금지
- **콘텐츠 유형 누락 없이** — SNS 콘텐츠 포함

### 지표
- 확보 시간 전부 숫자(시간)로 명시
- 구축 시간 절감 + 구축 후 연간 절감 시간 모두 기재
- "4x" 보다 "생산성 400% 달성" 표현이 더 임팩트
- **합산 시간 쓰지 않기** — 개별 항목 절감 시간만

### 확보 시간 재투자
- **재투자 대상을 다양하게** — "경영진 보고"만 반복하면 억지스러움
- 전략 고도화, 이미지 제작, 커뮤니케이션(팀/외부), 프로젝트 관리, BM 전략, 콘텐츠 고도화, 경쟁 전략, 고객·파트너 대응 등 적절히 배분
- "검토"만 쓰지 말고 **"고도화"** 표현도 적극 사용

### 표현 변형
- "비개발 직군" 표현은 유지 — 임팩트 있음
- 동사 다양하게: "직접 개발" 대신 "구축", "기획·구축", "설계·구축", "기획·설계·구축", "구축·배포" 등 변형
- 같은 문구가 모든 항목에 반복되면 복붙처럼 보임 → 항목별로 달리 표현

### 정기 업무 포함 원칙
- 매주 반복되는 보고·미팅(CTO 보고, 팀 주간보고, 듀얼랩 콜 등)도 건수 명시하여 반영
- CTO 주간보고는 매주 하는 거라 별도 건으로 부풀리지 않기 — 단, CTO 주간보고 외에 추가로 한 보고(CEO 보고, 별도 대표님 PT 등)는 별도 명시
- 보고 자료 작성·CEO 보고·외부 미팅 주도 등 리더십 활동 누락 금지
- "~직접 진행", "~주도", "~작성 및 보고" 등으로 주체성 표현

### 분기 경계·항목 구분 원칙
- Q1/Q2 경계 항목은 사용자에게 확인 후 분류
- AX 건에 포함된 리서치(유튜버 스코어링 등)는 PR 항목에 중복 기재하지 않기 — AX에서 커버
- 성과 문서화 작업 자체(Confluence AX 페이지 작성 등)는 별도 성과로 적지 않기
- Confluence PR 폴더 구조(사내 라운지, Medium, X 포스팅 등)에서 건수 크로스체크

### 입력 소스: Confluence PR 폴더
- `OSS1 > PO/PM 파트 > 마케팅 > PR 운영` — 사내 라운지, Medium, X, 보도자료 건수 확인
- `OSS1 > PO/PM 파트 > 마케팅 > PR 마일스톤` — 분기별 마일스톤 달성 현황
- `OSS1 > Dual Lab PR 상세 > Medium 아티클 초안/리뷰` — Medium 리뷰 건수 확인

## 워크플로우: /suji-performance growth

### Step 1: 데이터 수집

1. suji-report 분기 리포트 존재 여부 확인 → 없으면 `/suji-report {분기}` 먼저 실행 제안
2. **이번 분기 OKR 확인** — 사용자에게 OKR/KR 목록 요청 (텍스트, 스크린샷, 또는 파일 경로)
3. ERP 성과 목표 양식 확인 (사용자에게 스크린샷 또는 텍스트 요청)
4. 데일리 노트 + 월간 TODO 전수 스캔 — 정기 업무 건수 집계 포함
5. AX 사례 초안 참조
6. 팀원 성과 페이지 참조 (Confluence, 톤·분량 벤치마크용)

### Step 2: OKR 기준 매핑

사용자가 제공한 OKR/KR 항목별로 해당 분기 전체 업무를 매핑:
- AX 사례 (AI 활용 건)
- 정기 업무 (보고, 미팅, 계약 관리 등)
- 리서치·전략 산출물
- PR·홍보 활동
- 비즈니스 개발·파트너십

### Step 3: 초안 작성

가이드라인 전항목 적용하여 초안 생성.

**체크리스트 (Ralph Loop 대상):**
- [ ] 비용(만원) 수치 없음
- [ ] "완전 제거" 등 과장 표현 없음
- [ ] "AI 지원으로" 패턴 적용
- [ ] 비교 표현 없음 (조직 내 참고 자료 톤)
- [ ] 합산 시간 없음
- [ ] 확보 시간 재투자 대상 다양함
- [ ] 동사 항목별로 다름 (복붙 느낌 없음)
- [ ] 정기 업무 건수 포함
- [ ] CEO 보고·보고 자료 작성 포함
- [ ] 수치 근거 명시 (시간, 배수, 건수)
- [ ] 없는 사실 없음

### Step 4: 사용자 검토

초안을 사용자에게 보여주고 피드백 반영. 콘텐츠는 사용자 확인 없이 변경 불가.

### Step 5: 저장

```
~/Workspace/work/outputs/drafts/yyyymmdd_성장피드백_{분기}.md
```

## 주의사항

- 초안은 반드시 사용자에게 보여주고 확인받을 것
- 콘텐츠(텍스트/수치/강조점) 사용자 확인 없이 변경 불가
- 파일 저장 시 `~/Workspace/work/outputs/drafts/` + `yyyymmdd_제목.md` 컨벤션 준수
- 데이터가 없는 항목은 "데이터 없음" 명시
- **가이드라인 체크리스트는 Ralph Loop 대상** — 전항목 통과까지 반복, 3회 실패 시 사용자에게 보고
