# suji-prioritize

"다 중요하고 급해"를 풀기 위한 3-질문 우선순위 가이드. 알아서 정하지 않고, 질문으로 사용자가 직접 판단하도록 돕는다.

## 위치

```
/suji-work-minute (데일리 생성) → /suji-prioritize (P0~P3 배정) → /suji-work-minute close
```

## 사용법

```
/suji-prioritize           오늘 데일리 기준 전체 우선순위 가이드
/suji-prioritize weekly    이번 주 단위 정리
```

"우선순위 정하자", "뭐부터 해야 하지", "다 급해" 등으로도 트리거된다.

## 3-질문 프레임워크

### Q1. "이걸 안 하면 누가 막히나?"

태스크를 외부 대기(팀장/파트너/고객) → 내부 대기(내 다른 작업 블록) → 나만 대기로 분류한다.

### Q2. "이걸 하면 뭐가 풀리나?"

의존성 체인의 첫 노드를 식별한다. 컨펌 체인이 있으면 단계 수 x 1일로 역산하여 실제 마감일을 계산한다.

### Q3. "30분이면 끝나나?"

빈 시간에 치울 후보를 별도 표시한다. 단, P0보다 앞에 배치하지 않는다.

## P 레벨

| 레벨 | 의미 | 전형적 조건 |
|------|------|-----------|
| P0 | 오늘~이번 주 필수 | 평가 직결, 하드 데드라인 |
| P1 | 이번 주~다음 주 중요 | 외부 대기, 체인 첫 노드 |
| P2 | 해야 하지만 덜 급함 | P0/P1보다 후순위 |
| P3 | 급하진 않지만 해야 할 일 | 기한/대기자 없음 |

P 레벨은 일괄 배정하지 않는다. 가장 급한 항목부터 하나씩 사용자와 확인한다.

## 핵심 규칙

- 판단하지 않는다. 질문하고, 분류하고, 제안한다
- 사용자가 분류를 바꾸면 즉시 반영한다
- 레벨 제안 시 반드시 근거를 함께 말한다
- 개인 프로젝트는 기본 제외 (요청 시 포함)

## 입력 소스

- 오늘 데일리 노트 (`daily_task/yyyymmdd.md`)
- 월간 TODO (`monthly_task/YYYY Mon TODO.md`)
- 프로젝트 카드 (`project_todo/*.md`)
- Memory 활성 프로젝트

## 관련 스킬

| 스킬 | 관계 |
|------|------|
| `/suji-work-minute` | 데일리 노트 생성. 입력 소스이자 출력 대상 |
| `/suji-report` | 성과 리포트. 우선순위 판단 근거로 참조 |
| `/suji-cto-weekly-report` | 주간보고. P0/P1 항목이 주간보고 소재 |
