# /suji-research

리서치 수행부터 Confluence 업로드까지의 **품질 기준과 파일 관리**를 담당하는 스킬.
공통 규칙(제목, 레이아웃, 변환)은 `/suji-confluence-publish`, API 실행은 `/bundo-jira`에 위임한다.

## When to Trigger

- "리서치해줘", "조사해줘", "~에 대해 알아봐줘"
- "리서치 올려줘", "드래프트 올려줘", "컨플루언스에 올려줘"
- "리서치 동기화해줘", "초안 업로드해줘"
- ~/Workspace/work/drafts/ 또는 ~/Workspace/work/research/ 파일 작성·업로드 시

---

## 1. 출처 기준

리서치 결과물의 신뢰도는 출처가 결정한다. 아래 우선순위를 따른다.

| 우선순위 | 출처 유형 | 예시 |
|---------|----------|------|
| 1 | 학술 기관 공식 발행물 | MIT, Stanford, CMU |
| 2 | 표준 단체 공식 스펙 | W3C, IETF, ISO |
| 3 | 기술 기업 공식 문서 | 공식 블로그, 엔지니어링 블로그 |
| 4 | 피어리뷰 논문 | arXiv, ACM, IEEE |
| 5 | 정부/국제기구 보고서 | — |
| 6 | 해당 분야 공신력 인정 소스 | — |

**금지:** 개인 블로그, 비공식 소스를 1차 출처로 사용하지 않는다. 보조 참고만 가능.

---

## 2. 리서치 문서 구조

리서치 파일은 다음 구조를 따른다.

```markdown
---
title: "리서치 제목"
date: "YYYY-MM-DD"
sources: ["URL1", "URL2"]
status: draft | review | final
---

## TL;DR

> 핵심 결론 1~3문장. 수치 포함.

## 배경

왜 이 리서치가 필요한가.

## 조사 내용

### 소주제 1
- 내용 + 출처 명시

### 소주제 2
- 내용 + 출처 명시

## 비교/분석

테이블 또는 장단점 정리.

## 결론 & 제안

조사 결과 기반 액션 아이템.

## 출처

번호 매긴 출처 목록.
```

### 필수 요소

- **TL;DR**: 첫 섹션. 핵심 결과 + 구체적 수치 (e.g. "30% 절감", "6시간/월 절약")
- **출처 섹션**: 모든 인용에 번호 매긴 출처 명시
- **수치 명시**: "개선됨" 대신 구체적 수치. 수치 미확보 시 `[확인 필요]` 표기
- **비교 테이블**: 2개 이상 대안 비교 시 테이블 필수

| 용도 | 경로 | 파일명 규칙 |

## 4. Confluence 업로드 대상

| 파일 종류 | Confluence 경로 | Page ID |
|-----------|----------------|---------|
| 리서치 | OSS1 > 🔒 PO/PM 파트 > 리서치 | 1902903831 |
| 산출물 초안 | 문서별 지정 (업로드 시 확인) | — |

리서치 파일은 생성/수정 시 Confluence 리서치 페이지 하위에 동일 제목으로 동기화.

---

## 5. 로컬 전용 표기

Confluence에 올라가면 안 되는 로컬 전용 표기:

| 표기 | 용도 | 처리 |
|------|------|------|
| YAML frontmatter (`---`) | 페이지 정보, 데이터 소스, 작업 메모 | `md_to_confluence.py`가 자동 제거 |
| `<!-- LOCAL: ... -->` | 항목별 인라인 메모 | Confluence에서 렌더링 안 됨 |
| `[확인 필요]` | 사용자가 수치를 직접 채울 항목 | 잔존 시 업로드 전 사용자에게 보고 |

---

## 6. 업로드 전 체크리스트

업로드 실행 전 전항목 통과 확인 (Ralph Loop 적용):

- [ ] TL;DR 섹션 있음 + 구체적 수치 포함
- [ ] 출처 섹션 있음 + 모든 주장에 출처 번호 매핑
- [ ] 출처가 우선순위 1~5에 해당 (개인 블로그 1차 출처 없음)
- [ ] `[확인 필요]` 잔존 항목 없음 (있으면 사용자에게 보고)
- [ ] `<!-- LOCAL: ... -->` 주석이 의도대로만 남아있음
- [ ] 비교 대상 2개 이상이면 테이블 포함

---

## 7. 실행 가이드

### 리서치 수행 시

1. 사용자의 리서치 주제 확인
2. 출처 우선순위에 따라 조사 (공식 문서 우선)
3. 문서 구조(섹션 2)에 맞춰 작성
4. `~/Workspace/work/research/yyyymmdd_filename.md`로 저장
5. 업로드 전 체크리스트(섹션 6) 통과 확인

### Confluence 업로드 시

1. 대상 파일 확인 (`drafts/` 또는 `research/`)
2. 업로드 전 체크리스트(섹션 6) 실행
3. 업로드 대상 결정:
   - 리서치 → OSS1 > 리서치 (Page ID: 1902903831) 하위
   - 드래프트 → 사용자에게 대상 페이지 확인
4. 공통 규칙 적용 → `/suji-confluence-publish` (제목, 레이아웃, 변환)
5. API 실행 → `/bundo-jira` (curl, 버전 관리, 이미지 순서)
