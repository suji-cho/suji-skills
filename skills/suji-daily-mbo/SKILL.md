# suji-work-minute

Obsidian 데일리 노트 기반 업무 시간 관리. ERP MBO 입력의 원본 데이터.

**scope: work only**

## 파이프라인 위치

```
/suji-work-minute (데일리 입력)
    ↓
    ├─ /suji-work-minute mbo    (월별 취합 → ERP 참조용, 공수 집계)
    └─ /suji-work-minute weekly (주간 압축 리스트 → 보고·공유용, 사람이 읽는 형태)
    ↓
/suji-report (성과 리포트 소재)
/suji-cto-weekly-report (시간 배분 데이터)
```

## 설정

```
DAILY_BASE=~/Workspace/work/hand-ons/work_minutes/2026/daily_task
DAILY_PATH=$DAILY_BASE/YYYY Mon          # 월별 서브폴더 (예: "2026 Apr")
MONTHLY_TODO_PATH=~/Workspace/work/hand-ons/work_minutes/2026/monthly_task
PROJECT_TODO_PATH=~/Workspace/work/project/project_todo
REVIEW_PATH=~/Workspace/work/hand-ons/work_minutes/2026/ERP 공수 월별 리포트
```

## ERP 작업유형 (띄어쓰기 정확, 변경 불가)

- 프로젝트관리
- 회의
- 산출물 작성
- 리서치
- 교육
- 휴가
- 전사공통일정

## 커맨드

```
/suji-work-minute                → 오늘 노트 생성 + 할일 수집
/suji-work-minute yesterday      → 어제 노트 후속 입력
/suji-work-minute close          → 마감 정리 (공수 합산, projects 매칭)
/suji-work-minute mbo            → 이번 달 월별 취합 리스트
/suji-work-minute mbo 2026-03    → 특정 월 취합
/suji-work-minute weekly         → 이번주 한일·할일 압축 리스트 (보고·공유용)
/suji-work-minute weekly [붙여넣기] → 직전 주 리스트를 기준으로 갱신
```

## 데일리 노트 포맷

파일: `work/hand-ons/work_minutes/2026/daily_task/YYYY Mon/yyyymmdd.md`
예시: `work/hand-ons/work_minutes/2026/daily_task/2026 Apr/20260408.md`

```markdown
---
tags: [daily]
scope: work
date: YYYY-MM-DD
total_hours: 0
overtime_hours: 0
projects: []
---

# YYYYMMDD Daily

> ⚡ P0 즉시 치우기 · 📌 P1 오늘 집중 · 📅 P2 이번 주 · 🗂️ P3 다음 주 이후

| 우선순위 | 작업공수 | 작업유형 | 작업내용 | status |
|--------|--------|--------|--------|--------|
| ⚡ P0 |  | 프로젝트관리 | 긴급 메일 답변 |  |
| 📌 P1 |  | 산출물 작성 | 성장 피드백 작성 (마감 4/17) |  |
| 📅 P2 | 2 | 회의 | 팀회의, 기술전략팀 회의 |  |
| 🗂️ P3 |  | 리서치 | 접근성 법 리서치 |  |

## 메모

```

**우선순위 레벨:**
- `⚡ P0` — 즉시 치우기 (30분 이내, 오늘 중)
- `📌 P1` — 오늘 집중 (오늘의 메인 작업)
- `📅 P2` — 이번 주 내
- `🗂️ P3` — 다음 주 이후

**규칙:**
- 컬럼: 우선순위, 작업공수, 작업유형, 작업내용, status (5열)
- 작업공수 비어있음 = 할일 (미완료)
- 작업공수 채워짐 = 한일 (완료)
- status 컬럼: 사용자 개인 추적용 (예: 완료/진행/보류). 자유 입력. close/mbo는 건드리지 않음
- 작업유형은 반드시 위 ERP 목록 중 하나 사용
- 월별 서브폴더: `2026 Jan`, `2026 Feb`, ... `2026 Apr`
- mbo 취합 시 우선순위·status 칸은 무시, 작업공수/작업유형/작업내용만 추출

**야근 기록 (`overtime_hours`):**
- 야근한 날은 frontmatter `overtime_hours`에 **야근 시간만** 기록. 야근 없으면 `0`
- `total_hours`는 야근 포함 총 공수. 기본 근무 8h + 야근 2h인 날 → `total_hours: 10` · `overtime_hours: 2`
- **테이블 행이 아니라 frontmatter가 SoT.** 야근이 여러 작업에 걸쳐 있으면 특정 행에 귀속시킬 수 없기 때문
- status 칸에 `야근 N` 문구가 있어도 무방하나 참고용. 집계는 frontmatter만 사용
- 야근 시간을 별도 테이블 행으로 만들지 않는다. `total_hours`와 테이블 합계가 어긋남

## 기존 Notion 데이터

Notion에서 가져온 데일리 노트는 월별 폴더에 `Nth, Mon.md` 형식으로 존재 (예: `1st, Apr.md`).
테이블 헤더: `| 공수 | 유형 | 내용 |` (ERP 컬럼명과 다름).
새로 생성하는 노트만 ERP 컬럼명(`작업공수`, `작업유형`, `작업내용`) 사용.
mbo 시 두 포맷 모두 파싱 가능해야 함.

## 워크플로우

### `/suji-work-minute` — 아침 호출

1. **날짜 확인**: 오늘 `yyyymmdd`, 월 폴더명 결정 (예: `2026 Apr`)
2. **파일 존재 확인**: `work/hand-ons/work_minutes/2026/daily_task/YYYY Mon/yyyymmdd.md`
   - 없으면 → 템플릿에서 생성 (date, 제목 치환)
   - 있으면 → 읽기
3. **할일 자동 수집**:
   - 어제 데일리 노트에서 작업공수 비어있는 행 (캐리오버 — 미완료)
   - **어제 데일리 노트에서 작업공수 채워진 행** (🔁 이어가는지 확인 — 공수를 들였지만 완결되지 않은 다회성 작업 후보)
   - 현재 월간 TODO (`work/hand-ons/work_minutes/2026/monthly_task/YYYY Mon TODO.md`) 미완료 항목
   - 프로젝트 TODO 문서 (`work/project/project_todo/*.md`, done/ 제외) 미완료 항목
4. **수집 결과 보여주기**: 테이블 형태로 후보 제시. **모든 후보 행에 좌측 `#` 컬럼으로 번호 부여** (1, 2, 3 ... 블록별 연속 번호). "🔁 어제 완료 — 이어가는지 확인" 블록을 별도 표기하여 각 항목의 계속/종료 여부를 물을 것.
5. **사용자 선택**: 사용자가 번호("1, 3, 5")로 선택할 수 있도록 안내. 이어가는 항목은 계속/종료 판단 포함.
6. **변경 내용 보여주고 승인 후 저장**

### 업무 중 — 사용자 직접 편집

사용자가 Obsidian에서 직접:
- 새 행 추가
- 작업공수 채움 (완료 표시)
- 작업유형, 작업내용 입력

### `/suji-work-minute close` — 마감 정리

1. **오늘 데일리 노트 읽기**
2. **테이블 파싱**: 작업공수가 채워진 행만 추출
3. **total_hours 계산**: 작업공수 합산 → frontmatter 업데이트
4. **projects 매칭**: 작업내용 텍스트 → 월간 TODO/프로젝트 TODO 문서 매칭 → frontmatter 업데이트
4-1. **야근 확인**: `total_hours > 8` 이면 야근 여부를 물어보고 `overtime_hours` 업데이트
   - 기본 제안값 = `total_hours - 8`. 사용자가 다른 값을 주면 그 값 사용
   - 야근이 아니라 공수 입력 오류인 경우도 있으므로 **임의 확정하지 말고 반드시 확인**
   - `total_hours <= 8`이면 `overtime_hours: 0` 유지
5. **8시간 미만 경고**: total_hours < 8 이면 알림
6. **월간 TODO 크로스 업데이트 제안**: 완료된 항목이 월간 TODO에 있으면 체크 제안
7. **미완료 항목 확인**: 작업공수 비어있는 행 목록 보여주기 (내일 캐리오버 대상)
8. **변경 내용 보여주고 승인 후 저장**

### `/suji-work-minute mbo` — 월별 취합

1. **기간 결정**: 인자 없으면 이번 달, `2026-03` 형식이면 해당 월
2. **해당 월 데일리 노트 전체 읽기**: `work/hand-ons/work_minutes/2026/daily_task/YYYY Mon/*.md` glob
3. **테이블 파싱**: 각 파일에서 작업공수 채워진 행 추출 (우선순위 칸 무시)
   - 신규 포맷 (5열): `| 우선순위 | 작업공수 | 작업유형 | 작업내용 | status |`
   - 이전 포맷 (4열): `| 우선순위 | 작업공수 | 작업유형 | 작업내용 |`
   - 기존 포맷 (3열): `| 작업공수 | 작업유형 | 작업내용 |`
   - Notion 포맷 (3열): `| 공수 | 유형 | 내용 |`
3-1. **행 병합 (같은 일자 + 같은 작업유형)**:
   - 키: `(작업일, 작업유형)` — 같은 데일리 노트 안에서 동일 작업유형이 여러 행이면 한 행으로 합침
   - 작업공수: 숫자 합산 (소수점 1자리, 예: `2 + 1.5 → 3.5`)
   - 작업내용: `, ` 구분자로 결합, 완전히 동일한 문구는 중복 제거 (원래 입력 순서 유지)
   - 정렬: 작업일 오름차순 → 같은 일자 내에서는 합산 공수 내림차순
   - 원본 데일리 노트는 절대 수정하지 않음 (mbo 출력 단계에서만 병합)
3-2. **일자 구분 빈 행 (필수)**:
   - 작업일이 바뀌는 경계마다 빈 행 `|  |  |  |  |` 한 줄 삽입
   - 목적: 일자 그룹을 시각적으로 분리 → ERP 입력 시 날짜 단위로 읽기 쉬움
   - 첫 데이터 행 앞·마지막 행 뒤에는 넣지 않음 (그룹 사이에만)
   - 같은 일자 내 여러 작업유형 행 사이에는 넣지 않음
3-3. **야근 수집**: 각 데일리 노트 frontmatter의 `overtime_hours` 읽기 (없거나 `0`이면 야근 없음)
   - 헤더에 야근 요약 블록 출력 (일수·총 시간·일자별 내역)
   - 해당 일자 그룹의 **첫 행 작업일 셀에만** `🌙N h` 마커 부착 (예: `2026-04-02 🌙2h`)
     - 같은 일자의 두 번째 행부터는 마커 없이 날짜만
     - 야근 없는 날은 마커 없음
   - 마커는 사람이 읽는 참조용. ERP 입력 시 날짜만 옮기면 됨
4. **취합 리스트 생성**:

```markdown
# 2026년 04월

📊 누적 공수: 22.0h
🌙 야근: 2일 / 3.0h

🌙 야근 일자
  • 2026-04-02 — 2.0h (총 10.0h)
  • 2026-04-08 — 1.0h (총 9.0h)

⚠️ 8시간 미만 입력 날짜
  • 2026-04-03 — 6.0h

| 작업일 | 작업공수(ManHour) | 작업유형 | 작업내용 |
|--------|-----------------|--------|--------|
| 2026-04-01 | 6 | 프로젝트관리 | 미디움 자동화, 회의록 작성 업데이트, KB 구축 |
| 2026-04-01 | 2 | 회의 | 팀회의, 기술전략팀 회의 |
|  |  |  |  |
| 2026-04-02 🌙2h | 8 | 프로젝트관리 | KB 구축, 회의록 자동화 구축 |
| 2026-04-02 | 2 | 회의 | 팀회의 |
```

> 병합 예시: 2026-04-01 데일리에 `프로젝트관리 4h — 미디움 자동화` / `프로젝트관리 2h — KB 구축` 두 행이 있으면, 위처럼 한 행 `6h — 미디움 자동화, KB 구축`으로 합쳐진다.
> 빈 행 예시: 위 04-01 그룹과 04-02 그룹 사이의 `|  |  |  |  |` 한 줄. 일자가 바뀔 때마다 반복.
> 야근 마커 예시: 04-02는 총 10h 중 2h가 야근 → 그룹 첫 행에만 `2026-04-02 🌙2h`. 야근 시간을 별도 행으로 분리하지 않는다.
> 야근 정합성 검증: `overtime_hours > 0`인데 `total_hours <= 8`이면 불일치이므로 경고 출력 후 사용자 확인.


5. **미입력 영업일 경고**: 해당 월에 데일리 노트가 없는 평일 목록
6. **파일 저장**: `work/hand-ons/work_minutes/2026/ERP 공수 월별 리포트/yyyymm_월간요약.md`에 저장
7. **변경 내용 보여주고 승인 후 저장**

### `/suji-work-minute weekly` — 주간 한일·할일 압축 리스트

데일리 노트 여러 개를 **보고·공유용 한 덩어리 리스트**로 압축한다. mbo가 ERP 공수 집계용이라면, weekly는 **사람이 읽는 진행 상황 공유용**이다.

**입력 우선순위**
1. 사용자가 직전 주 리스트를 붙여넣으면 그것이 기준 (그 이후 구간만 새로 작성)
2. 없으면 이번주 월요일 ~ 오늘 구간의 데일리 노트를 읽어 작성

**소스**
- 데일리 노트 (`DAILY_PATH/yyyymmdd.md`) — 테이블 행 + `## 메모` 의 스케줄·백로그·확인 필요 블록
- 필요 시 회의록 (`hand-ons/meeting_minutes/`), 이메일 등 외부 증거로 상태 보강

#### 출력 포맷 (고정)

**반드시 코드블록**으로 출력한다 (불렛이 일반 렌더 시 복사·입력 안 되는 이슈).

```
* 항목명 (상태, 날짜)
  - 부연 1
  - 부연 2
```

- 최상위 항목 = `* `, 부연 = `  - ` (스페이스 2칸 + 대시)
- 상태 라벨: `완료` · `진행` · `예정` · `딜레이` · `대기` · `상시`
- 날짜: 단일 `8/6` 또는 구간 `8/4 ~ 8/11` 또는 마감 `~ 8/13`. 진행 중 시작만 있으면 `8/7 ~`
- 한일·할일을 **섹션으로 나누지 않는다.** 상태 라벨이 구분자 역할을 하므로 한 덩어리 리스트로 유지
- 부연은 **항목당 최대 2줄.** 그 이상은 항목이 쪼개져야 한다는 신호

#### 압축 규칙 (핵심)

이 커맨드의 본질은 **덜어내기**다. 데일리 노트를 그대로 옮기면 실패다.

| 규칙 | 적용 |
|------|------|
| **동종 병합** | 같은 성격 항목은 한 줄로. 예: 계약 2건 → `계약 2건 법무검토, PDF4WCAG·듀얼랩 하반기` / 회의 여러 건 → `ODL + DL 검증 미팅, 팀 주간회의` |
| **단계 접기** | 한 프로젝트의 일자별 진행은 항목 1개 + 부연 1~2줄로. 일자별 행을 나열하지 않는다 |
| **잡무 삭제** | 회의록 작성, 노트 정합 정리, 리뷰 완료 등 결과물 공유 가치 없는 항목은 뺀다 |
| **미확정 묶기** | 열린 이슈는 개별 항목이 아니라 부연 한 줄에 가운뎃점으로 나열 |
| **분량 상한** | 최상위 항목 **12개 이내**. 초과하면 병합·삭제를 한 번 더 돌린다 |

#### 워크플로우

1. 직전 주 리스트 확보 (붙여넣기 또는 이번주 시작일 판단)
2. 구간 데일리 노트 전부 읽기 (테이블 + 메모)
3. 프로젝트 단위로 그룹핑 → 상태·날짜 확정
4. 압축 규칙 적용 → 12개 이내로 축약
5. 코드블록 출력
6. 코드블록 **밖**에 짧게 첨부:
   - 취합·삭제한 항목 한 줄 요약 (무엇을 덜어냈는지 투명하게)
   - `확인 필요` 항목 (노트 간 충돌·미확정 일정·근거 부족)

#### 규칙

- **데일리 노트가 SoT.** 노트에 없는 작업을 추론으로 만들어내지 않는다
- **노트 간 상태 충돌은 임의 봉합 금지·보고.** 예: 백로그에 "대기"로 남아 있으나 외부 증거상 종결된 항목
- **근거 없는 수치·일정 단정 금지.** 미확인은 `확인 필요`로 분리
- 엠대시(`—`) 사용 금지. 라벨은 콜론, 나열은 가운뎃점
- 틸드는 앞뒤 공백 (`8/4 ~ 8/11`). 단 경로 틸드는 예외
- **파일 쓰기 없음.** 기본은 코드블록 출력만. 사용자가 요청하면 위치 확인 후 저장

## 테이블 파싱 규칙

마크다운 테이블에서 데이터 추출 시:
1. 헤더행 찾기: `| 작업공수 |` 또는 `| 공수 |` 포함된 행
2. 구분선(`|---|`) 건너뛰기
3. **헤더 기반 컬럼 인덱스 결정**: 헤더행을 `|` 기준 split → trim하여 컬럼명별 index 매핑
   - 필수 컬럼: 작업공수(또는 공수), 작업유형(또는 유형), 작업내용(또는 내용)
   - 우선순위 칸이 있으면 인덱스만 기록하고 **close/mbo 파싱에서는 무시**
   - 추가 컬럼은 무시해도 파싱에 영향 없음
4. 데이터 행 파싱: `|` 기준 split → 헤더에서 결정한 index로 각 필드 추출
5. **전 셀이 빈 행은 건너뛰기** — mbo 월간요약의 일자 구분 빈 행(`|  |  |  |  |`)이 데이터로 잡히지 않도록. 재취합 시에는 기존 빈 행을 전부 제거한 뒤 다시 삽입
6. 작업공수/공수가 빈 문자열이면 미완료 (할일) — 다음날 캐리오버 대상. **임의로 공수를 채우지 않는다**
7. 작업공수/공수가 숫자면 완료 (한일)

**4가지 테이블 포맷 호환:**
- 신규 포맷 (5열): `| 우선순위 | 작업공수 | 작업유형 | 작업내용 | status |`
- 이전 포맷 (4열): `| 우선순위 | 작업공수 | 작업유형 | 작업내용 |`
- 기존 포맷 (3열): `| 작업공수 | 작업유형 | 작업내용 |`
- Notion 포맷 (3열): `| 공수 | 유형 | 내용 |`
