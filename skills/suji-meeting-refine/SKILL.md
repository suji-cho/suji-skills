# 회의록 정리 및 Confluence 업로드

## When to Trigger
- "회의록 정리해줘"
- "/suji-meeting-refine"

## 개요

옵시디언에 작성한 회의록 원본 메모를 읽고, Confluence용 구조화 포맷(결론 표 + AI 정리 + 원본 code block)을 생성하여 업로드한다.
**옵시디언 원본 파일은 수정하지 않는다.**

## 옵시디언 정보

- Vault 경로: `~/Workspace/`
- 업무 회의록: `~/Workspace/work/hand-ons/meeting_minutes/`
- 개인 회의록: `~/Workspace/personal/personal/`
- 월간 TODO: `~/Workspace/work/hand-ons/work_minutes/2026/monthly_task/`
- 파일명 규칙: `yyyymmdd_제목.md`

### 옵시디언 파일 구조 (입력)

옵시디언 파일은 아래와 같은 심플 포맷이다. 이 구조를 그대로 유지한다.

```markdown
#해시태그

날짜: yyyymmdd
참석: 
안건: 

---

# 회의록

### 소주제
* 메모
* 메모
```

- 태그: 파일 첫 줄 해시태그 (`#연구소`, `#컨콜`, `#팀`, `#기타`, `#개인`)

## 워크플로우

### Step 1. 대상 파일 확인

사용자가 파일을 지정하거나, 가장 최근 수정된 옵시디언 파일을 대상으로 한다.
- 첫 줄 해시태그로 태그 추출 (예: `#연구소 #경쟁사대응`)
- `#개인` 태그면 Confluence 업로드 제외, TODO 수집만 진행

### Step 2. 결론 추출

원본 메모에서 아래 3가지를 추출한다.

| 구분 | 추출 기준 |
|------|----------|
| 결정 | 회의에서 확정된 사항 |
| 액션 | 누가 뭘 해야 하는지 (`@담당자` 포함) |
| AI 요약 | AI가 원본 메모를 한줄 요약 |

### Step 3. AI 정리

원본 메모를 읽기 쉽게 구조화한다.
- 중복 제거, 문맥 보완
- 불릿 계층 정리
- 원본의 의미를 변경하지 않음

### Step 4. Confluence 포맷 생성 및 업로드

옵시디언 원본은 수정하지 않고, Confluence용 구조화 포맷을 생성하여 업로드한다.

**Confluence 포맷:**

````markdown
## 결론

| 구분 | 내용 |
|------|------|
| 결정 | (확정 사항) |
| 액션 | (액션 아이템 @담당자) |
| AI 요약 | (원본 메모 한줄 요약) |

---

## AI 정리

(구조화된 내용)

---

## 원본 메모
```
(옵시디언 원본 전체 내용)
```
````

- 첫 줄 해시태그로 Confluence 폴더 결정
- 페이지 제목 = 옵시디언 파일명 (확장자 제외)
- contentFormat: markdown
- 같은 제목의 페이지가 있으면 업데이트

**사용자에게 Confluence 업로드 내용을 보여주고 승인받은 뒤 업로드한다.**

### Step 5. TODO 수집

결론의 **액션** 항목을 옵시디언 TODO 파일에 추가한다.

- 경로: `~/Workspace/work/hand-ons/work_minutes/2026/monthly_task/`
- 파일명: `2026 Apr TODO.md` (월별)
- 형식:

```markdown
## From yyyymmdd_제목
- [ ] 액션 아이템 @담당자
```

- 해당 월 파일이 없으면 새로 생성
- 이미 같은 항목이 있으면 중복 추가하지 않음

## 주의사항

- **옵시디언 원본 파일은 수정하지 않음**
- Confluence 업로드 내용은 사용자 승인 후 반영
- 디자인·콘텐츠 사용자 확인 없이 변경 불가
- `#개인` 태그 파일은 Confluence 업로드 제외
