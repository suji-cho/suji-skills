# suji-biz-weekly

OpenDataLoader 제품 문의 대응 현황을 **매주** 갱신한다. Gmail `OSS/BIZ contact` 라벨을 확인해 신규 문의·회신을 반영하고, 신규 리드는 사업성 v1.3로 점수 산정하며, 전 항목 대기일을 오늘 기준으로 재계산해 **정해진 코드블록 양식**으로 출력한다.

**scope: work only**

## 커맨드

```
/suji-biz-weekly          → 직전 현황 리스트를 입력받아 이메일 확인·반영·갱신
/suji-biz-weekly [붙여넣기] → 직전 리스트를 붙여넣으면 그 기준으로 업데이트
```

## 전제

- **직전 현황 리스트가 입력(SoT)** — 사용자가 붙여넣은 리스트가 기준. 임의로 라벨·그룹·비즈니스 흐름을 바꾸지 않는다 ([[feedback_no_label_or_flow_rename]]).
- **점수 기준**: `~/Workspace/work/outputs/odl_business/governance/criteria/v1.3_20260601/` (criteria v1.3)
- **룰북(참고용)**: `~/Workspace/work/outputs/odl_business/contacts/biz_contact_tracker.md` (스키마 v2.2 — 양식이 다르므로 자동으로 덮어쓰지 않음)
- **Gmail 라벨**: `OSS/BIZ contact` (ID는 매번 list_email_labels로 확인)

## 워크플로우

### Step 1: 직전 리스트 확보

- 사용자가 직전 현황 리스트를 붙여넣으면 그것을 기준으로 삼는다.
- 없으면 사용자에게 직전 리스트를 요청한다. (직전 리스트의 마지막 활동일·대기일 기준이 비교 기준점)

### Step 2: Gmail 신규 활동 확인 (Gmail MCP 사용)

> 브라우저 handoff 불필요. **Gmail MCP 도구**를 쓴다 (`mcp__gmail__*`). 도구 미로드 시 ToolSearch로 로드.

1. `mcp__gmail__list_email_labels` → `OSS/BIZ contact` 라벨 ID 확인
2. 직전 리스트에 반영된 **가장 최근 날짜 이후**로 검색 (보통 직전 갱신일):
   ```
   mcp__gmail__search_emails  query: label:"OSS/BIZ contact" after:YYYY/MM/DD
   mcp__gmail__search_emails  query: subject:"Contact request" after:YYYY/MM/DD
   ```
   - `Contact request from X` = 신규 인바운드 (form 제출). 중복 제출(같은 이름·시각) 1건 처리.
   - `Re: Contact request from X` = 기존 스레드 회신 (외부 발신이면 상대 회신, 우리 발신이면 우리 액션).
3. 신규·회신 메일 각각 `mcp__gmail__read_email`로 원문 확인 → 이름·이메일·직책·소속·문의 요약 추출.
4. **확인 결과를 사용자에게 먼저 보고** (신규 N건, 회신 N건, 변동 없음 항목).

### Step 3: 신규 리드 점수 산정 (criteria v1.3)

신규 인바운드는 criteria v1.3 산식으로 점수 산정 (필요 시 criteria 파일 정독).

- **사전 Gate**: PDF 접근성·파싱 무관 / 학생 개인 / 정보 부족(이름+이메일뿐) → `[Cold·1차판단]` 또는 `미정`. funnel 가치 있으면 점수 모델 진입.
- **4축 (100점, cap 해제)**:
  - 축1 매출잠재력 30 (볼륨 15 + 조직규모 15)
  - 축2 네임밸류 35 (인지도 15 + 섹터대표성 10 + 규제위치 10)
  - 축3 확산력 15 (섹터파급 6 + 채널 5 + 규제연쇄 4)
  - 축4 실행 20 (실현 7 + 적극 8 + 데드라인 5)
- **컷오프**: P1 ≥70 / P2 40~69 / P3 20~39 / 미정 <20
- **자동 +1 룰**: 섹터대표성 ≥8(ODL Phase 핵심·미국 R1대학/시·주·연방) AND 총점 40~69 → P2→P1 (사유 "ODL Phase 핵심 타겟 자동 상향")
- **신규 인바운드 적극성**: 첫 인입은 응답 사이클 없음 → 상세+긴급+의사결정자면 보통 상단(6), 단답·정보부족이면 하향.
- **점수 산정 시 환각 무관용** ([[feedback_hallucination_zero_tolerance]]): 볼륨 등 미기재 항목은 추정하지 말고 "미확인" 점수 부여 + 업사이드 메모. 채널·전략 가치가 점수보다 높으면 산식 점수 + PM 검토 포인트 분리 제시 ([[feedback_pm_liability_shield]]).
- **점수 breakdown 표**를 사용자에게 보여줘 투명하게 (4축 + 합계 + Priority + 자동룰 적용 여부).

### Step 4: 대기일 전 항목 재계산

- 모든 항목 "대기 N일" = (오늘 − 마지막 활동일). 직전 리스트의 대기일은 기준일이 섞여 있을 수 있으므로 **전부 오늘 기준 재계산**.
- 일수 계산은 day-of-year 기준 정확히 (2026은 평년·2월 28일).
- 마지막 활동일(`날짜`)은 그대로 두고 N일만 갱신. 신규는 인입일이 마지막 활동일.

### Step 5: 그룹 배치

- **신규 인바운드**(우리 첫 답변 필요)는 기본 **진행 그룹**에 편입 (2026-07-01 사용자 결정). `[신규 문의 — 첫 답변 필요]` 프리픽스 + `(우리 차례, 날짜 · 대기 N일)`.
- 기존 항목 그룹은 직전 리스트 배치를 유지. 이메일 증거로 상태가 바뀐 경우만 이동하고, 이동 시 사용자에게 보고.
- 룰북(`biz_contact_tracker.md`)과 그룹 배치가 충돌하면 **임의 봉합 금지·보고** ([[feedback_memory_crosscheck]]).

### Step 6: 출력 (고정 양식)

**반드시 코드블록**으로 출력 (불렛이 일반 렌더 시 입력 안 되는 이슈 — 2026-07-01 사용자 요청). 들여쓰기·기호 그대로:

```
* [현황] 제품 문의 대응 (진행, 상시) — 전체 N건, 진행 N건, 답변 대기 N건, cold N건
* 진행 (N건)
  - 이름, [국가/B2X] 소속, 직책 — [프리픽스] 컨텍스트 요약, P?(점수) (상태, M/D · 대기 N일)
  - ...
* 답변 대기 (N건)
  - ...
* cold (N건)
  - ...
```

양식 규칙:
- 최상위 그룹 헤더 = `* `, 항목 = `  - ` (스페이스 2칸 + 대시).
- 항목 구조: `이름, [국가/B2X] 소속, 직책 — [프리픽스] 컨텍스트, P등급(점수) (상태, 마지막활동일 · 대기 N일)`
- 인명은 풀네임 ([[feedback_bm_person_name_format]]). "파트너십·마케팅" 풀네임 ([[feedback_no_pm_abbreviation]]).
- 틸드 앞뒤 공백 ([[feedback_tilde_spacing]]).
- 헤더 카운트는 실제 항목 수와 일치시킨다.

### Step 7: 변경 요약 (코드블록 밖)

코드블록 뒤에 짧게:
- ➕ 신규 N건 (점수·등급)
- 🔄 대기일 오늘 기준 재계산
- 카운트 변화 (예: 24 → 26건)
- ⚠️ 충돌·기한 도래 등 플래그

## 규칙

- **직전 리스트 = SoT.** 라벨·그룹·흐름 임의 변경 금지. 변경은 이메일 증거 기반 + 보고.
- **변경 전 확인은 점수·그룹 신설 등 판단이 필요한 경우만** — 단순 대기일 재계산·신규 반영은 보고 후 출력.
- **파일 쓰기는 사용자 확인.** 기본은 코드블록 출력만. 사용자가 "파일 반영"을 요청하면 위치 확인 후 작성.
- **PII 안내**: 외부 담당자 이름·이메일 포함 시 응답 말미 1줄 안내 (조직 정책).
- **답변 초안은 별도** — 신규 건 영어 답변 초안이 필요하면 `/suji-biz-reply`로 연계.
