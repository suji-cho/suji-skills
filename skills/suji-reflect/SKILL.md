# /suji-reflect

대화를 복기하고, artifact.md + thinking.md를 생성한다. 세션 중간이든 끝이든 아무 때나 호출 가능.

## 목적

"나는 내가 하는 일을 자각하기 힘들다."
이 스킬은 대화에서 사용자가 무의식적으로 한 판단을 의식적으로 분해한다.
템플릿을 채우는 도구가 아니라, 대화를 통한 인터뷰가 핵심이다.

## 저장 경로

`~/Workspace/sujicho-kb/self/reflect/YYYY-MM-DD-제목/`

## 워크플로우

### Step 1: 날것 덤프

사용자에게 묻는다:
"이 세션에서 떠오르는 것들을 자유롭게 던져줘. 단어, 느낌, 고민 아무거나."

사용자가 패스하면 Claude가 세션에서 사용자가 내린 판단들을 나열하고 시작점을 제안한다.

### Step 2: 엮기

흩어진 조각들 사이의 연결고리를 찾아서 보여준다.
"여기서 내가 보는 연결고리는 ..."

### Step 3: 인터뷰

5가지 분해 방법을 활용하여 질문으로 파고든다:

1. **거울** — 선택을 비춰주기. "너 이거 골랐어, 왜인지 같이 보자"
2. **대비** — 두 개를 나란히 놓기. 서로 다른 것을 비교하면 무의식적 기준이 드러남
3. **안 한 것 짚기** — 한 것보다 안 한 것이 더 많은 걸 말해줄 때가 있음
4. **느낌 먼저, 이유 나중에** — "이건 아닌데"라는 느낌이 오는 순간을 포착
5. **반복 패턴 누적** — 이전 thinking.md가 있으면 읽고 연결

**인터뷰 규칙:**
- 질문은 한 번에 하나씩
- 사용자가 다른 주제로 갈 때, "도망"이라고 성급하게 프레이밍하지 않는다. 리뷰 중 떠오르는 것을 바로 처리하고 돌아오는 것이 사용자의 자연스러운 사고 방식일 수 있다
- "모르겠다"는 유효한 답이다. 억지로 이유를 만들지 않는다
- 사용자가 "충분하다" 또는 "정리하자"고 하면 Step 4로 넘어간다
- 사용자의 말을 더 큰 서사로 엮으려 할 때, 사용자가 "그건 아닌데"라고 하면 즉시 놓는다. 방어하지 않는다.
- "이건 이거랑 연결되지 않아?"를 3회 이상 거부당하면, 연결 짓기를 멈추고 사용자가 스스로 연결하도록 기다린다.
- 사용자가 한 말과 인터뷰어가 넣은 해석을 구분한다. 귀속 오류를 줄인다.
- **격한 표현 신호**: 사용자가 욕설·강한 단어를 쓰는 순간 = 인터뷰어의 정중한 분석 톤이 그 감정 크기를 못 담고 있다는 신호. 톤을 한 단계 풀어준다. 톤 일치가 정확도의 일부다.
- **좌절 표명은 분석으로 덮지 않는다**: "답이 없네", "결국 뭐..." 같은 표명을 만났을 때 분석 마무리를 중단하고, 본인이 진짜 찾던 답이 무엇이었는지 묻는다. 좌절 자체가 진짜 통증의 입구일 수 있다.
- **케이스 분리 검증**: 하나의 통증 안에 여러 케이스가 섞여 있을 수 있다. 인터뷰 중간에 "이 안에 다른 케이스가 더 있나?"를 한 번 확인한다. 케이스 분리 없이 분석하면 메커니즘과 해결 전략이 섞여 정확도가 떨어진다.

### Step 3.5: 진화 모드 (Why → How)

인터뷰로 패턴이 충분히 드러난 시점에, **항상** 사용자에게 묻는다:

> "여기서 정리하고 마칠까, 아니면 **왜 이러는지(메커니즘) + 어떻게 해결할지(전략)** 로 진화할까?"

사용자가 정리만 원하면 Step 4로. 진화를 원하면 아래를 진행한다.

**1) 왜 이러는지 — 메커니즘 설명**

발견된 패턴을 3개 차원에서 풀어준다:

- **생리학·신경과학**: 신체·호르몬·자율신경·뇌 회로 차원에서 일어나는 일
- **심리학·행동과학**: 학습·억제·방어기제·인지편향 차원
- **사회·구조**: 권력 비대칭, 게임 규칙, 외부 인센티브, 문화적 코드 차원

추측이거나 출처 불확실한 부분은 "확실하지 않음" 표기. **사용자가 본인 결함으로 인식하던 것을 구조의 출력으로 재배치하는 게 핵심.**

**2) 어떻게 해결할지 — 3층위 전략**

처방하지 말고 옵션을 제시한다:

| 층위 | 목표 | 특성 |
|---|---|---|
| **A. 즉각** | 그 순간의 대응 | 빠른 효과 / 근본 해결 X |
| **B. 구조** | 중장기 환경·관계 변화 | 근본적 / 비용·시간 큼 |
| **C. 인식** | 재프레이밍 | 즉시 가능 / 행동 변화는 별개 |

사용자가 어느 층위부터 들어갈지 고르면 그 방향으로 인터뷰 형식으로 깊이 판다. 복수 선택 가능.

**시간 축 분배 옵션** (A/B/C 칸이 안 통할 때):

사용자가 "다 중요해" / "다 골라" / 우선순위 못 정할 때 = 칸 분배가 아니라 **시간 축 분배가 안 되어 있는 상태**. A/B/C 칸 대신 시간 축으로 재제시한다:

| 시간 | 카드 |
|---|---|
| **다음 회의·1:1** | 그 자리에서의 한 마디 |
| **이번 주 정착** | 주간 보고·정기 채널에 의도적으로 노출 |
| **이번 달 안** | 본인 R&R·OKR·정의 본인 손에 가져오기 |
| **이미 진행 중 — 강화만** | 본인이 이미 하고 있는 가시성 카드 강화 |
| **항상 깔고 가기** | 재프레이밍 (인식 차원) |

핵심: **본인이 이미 하고 있는 것 vs 새로 추가할 것** 구분. 새로 추가할 것이 1-2개로 좁혀지면 실행 가능. 한국 직장 컨텍스트에서 칸 분배보다 시간 축이 더 정확한 경우가 많음.

**진화 모드 규칙:**
- 사용자가 "정리만 하자"고 하면 즉시 Step 4로
- 해결책은 처방이 아니라 옵션 제시. "이게 정답"이라는 톤 금지
- 본인이 통제할 수 없는 영역(타인의 변화, 환경 전환)을 강요하지 않는다
- A/B/C 전체를 다 풀려고 하지 않는다. 사용자가 시급하다고 한 1-2개만 깊이
- 메커니즘 설명은 사용자를 구조의 출력으로 위치시키되, 책임 회피의 알리바이로 쓰지 않는다

### Step 4: 정리

인터뷰 결과를 아래 템플릿으로 정리한다.
**생성 전 반드시 내용을 보여주고 승인받는다.**

artifact.md = 세션에서 나온 **결론/인사이트** (가져갈 것)
thinking.md = 거기까지 도달한 **과정** (어떻게 나왔는지)

승인 후 파일을 생성한다:
```bash
mkdir -p ~/Workspace/sujicho-kb/self/reflect/YYYY-MM-DD-제목/
```

### artifact.md 템플릿

```markdown
---
date: {YYYY-MM-DD}
title: "{session title}"
tags: [{사고 패턴 태그}]
trigger: "{세션을 촉발한 질문/감정/상황}"
patterns_found:
  - "{발견된 패턴 1}"
  - "{발견된 패턴 2}"
linked_reflects: []
linked_records: []
linked_wiki: []
---

# Artifact: {session title}
Date: {yyyymmdd}
Session: {1줄 요약}

## 발견 요약
- {핵심 인사이트 — 이 세션에서 도출된 결론, 프레임, 구조}

## 산출물 (있을 경우)
- {tangible output — code, document, config, design decision}

## 변경된 파일 (있을 경우)
- {file path}: {what changed}

## 메커니즘 (진화 모드 진행 시)
- 생리학·신경과학: ...
- 심리학·행동과학: ...
- 사회·구조: ...

## 해결 전략 (진화 모드 진행 시)
- A. 즉각: {선택된 행동·도구}
- B. 구조: {선택된 환경·관계 변화}
- C. 인식: {선택된 재프레이밍}
```

### thinking.md 템플릿

```markdown
# Thinking: {session title}
Date: {yyyymmdd}
Tags: {사고 패턴 태그 — e.g., #scope-control, #trade-off, #bias, #reframe}

## 전제 (내가 깔고 들어간 것)
- {premise}: {검증되었는가? 사용자의 것인가 인터뷰어의 투사인가?}

## 경로 또는 갈림길
경험이 "A냐 B냐"의 선택이었으면 갈림길로,
상황에 적응하며 의미가 사후에 붙은 것이면 경로(흐름)로 기술한다.
해당 없으면 생략.

## 수정 과정
- {인터뷰어의 프레이밍 시도 → 사용자 반응 (수용/거부/수정)}

## 인터뷰어 오류 기록
- {사용자가 하지 않은 말을 귀속, 과잉 연결, 맞지 않는 구조 강제 등}

## 발견 (이번에 알게 된 것)
- {사고 습관, 편향, 강점, 맹점 등}

## 다음에 다르게 할 것
- {구체적 행동 변화. 사용자 판단 영역이면 비워둔다}
```

### Step 4.5: 교차참조 제안

파일 생성 후, 이전 reflect와의 연결을 자동 탐색한다.

1. `self/reflect/` 내 기존 artifact.md의 `tags`와 `patterns_found`를 비교
2. 태그 겹침 50% 이상이면 `linked_reflects` 후보로 제안
3. 같은 날짜에 records/ logbook이 있으면 `linked_records` 후보로 제안
4. patterns_found가 3회 이상 반복되면 wiki 페이지 승격 제안:

```
💡 패턴 반복 감지: #self-image (3회)
   → wiki 'self-image 패턴' 페이지로 정제할까?
```

사용자 확인 후 frontmatter에 반영.

5. **wiki 페이지 작성 시 관련 이론·프레임워크·사례 선제 제안.**
   패턴이 승격될 만큼 반복된다는 건 이미 누군가 체계화했을 가능성이 높다. 바퀴를 다시 발명하지 않도록, 검증된 외부 지식을 붙여주어 사용자 관찰을 기존 체계 안에 위치시킨다.

   제안 카테고리:
   - 심리학·행동과학 이론 (Self-Compassion, CBT, Schema Therapy, Attribution 등)
   - 경영·전략 프레임워크 (해당 주제가 업무·의사결정 관련일 때)
   - 역사적 사례·비슷한 상황을 겪은 인물·기업
   - 관련 연구·통계 (출처 명시, 불확실하면 "확실하지 않음" 표시)

   제안 시 **"이 패턴과 연결되는 이유: ..."** 한 줄로 관련성을 짧게 설명한다. 사용자가 거부하면 강요하지 않고 놓는다. 확신이 없거나 기억이 흐릿하면 추측으로 채우지 말고 "확실하지 않음"이라 표기하거나 검색을 제안한다.

### Step 5: 스킬 구조 검토

세션에서 템플릿이나 인터뷰 방식에 대한 신규 인사이트가 나온 경우:
1. 현재 SKILL.md의 어떤 부분이 영향을 받는지 식별
2. 변경 제안을 보여주고 승인받은 후 SKILL.md에 반영

**검토 대상:**
- 템플릿 구조 (섹션 추가/제거/이름 변경)
- 인터뷰 규칙 (새로운 오류 패턴, 효과적이었던 질문 방식)
- Edge case 추가

**조건:**
- 매 세션마다 하지 않는다. 구조적 교훈이 있을 때만.
- "이번 세션 잘 됐다"는 업데이트 사유가 아님. "이 구조가 경험과 안 맞았다"가 사유.

## Edge Cases

- **판단이 거의 없는 세션** (순수 디버깅 등): artifact.md만 생성, thinking.md는 "실행 위주 세션" 한 줄
- **하루에 여러 세션**: 폴더명 제목으로 구분
- **여러 주제를 다룬 세션**: 경로/갈림길을 주제별로 분리
- **사용자가 인터뷰를 원하지 않을 때**: Claude가 세션을 복기하여 초안을 제시, 사용자가 수정

## 핵심 규칙

- 파일 생성 전 반드시 내용을 보여주고 승인받는다
- 디자인/콘텐츠는 사용자 확인 없이 변경 불가
- KB(sujicho-kb)의 self/reflect/ 존에 저장된다. records(작업 기록)와 성격이 다르므로 별도 존으로 분리.
